## How to run and check

- `.claude/launch.json` has two configurations:
  - `portal-dev`: real Firebase sign-in. Firestore holds the owner's real
    data, so anything changed locally changes it.
  - `portal-dev-noauth`: no login, the local SQLite store, sample adapter.
  In the Claude desktop browser pane, start it with `preview_start`.
- With the no-auth server running, `node scripts/seed-local-tracker.mjs`
  loads sample applications into the local store only.
- `VITE_DATA_MODE=mock|http` picks the adapter; the default is mock in
  `vite dev` and http in a production build.
- Google sign-in does not work in the Claude browser pane (the popup loses
  its session storage); the owner signs in from Safari.
- Browser pane gotcha: with an emulated viewport larger than the pane,
  screenshot coordinates do not match page coordinates. Use the "desktop"
  preset and click by element ref.
- Tailwind is active, so a class named like a utility (`fixed`, `hidden`,
  `block`, `flex`, `grid`, `table`, `static`) picks up Tailwind's styles.
  That stacked the 履歴書 rows once; prefix new class names.
